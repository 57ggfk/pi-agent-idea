# 020 模型选择器：供应商数量上限 + 每家动态截断 + 组标题左对齐 + 搜索态折叠

> 来源：用户 2026-11-10 需求（原文一条，含五点）——「模型选择框，可按供应商折叠，供应商标题居左，搜索结果也要折叠，每个供应商也要展示最多展示 50 个供应商。供应商少于 5 个时，每个供应商最多展示 200 个模型，供应商多了还要限制每个供应商最多显示的模型个数，动态计算，最多的限制卡在至少 5 个。」
> 版本归属：**0.5.7**（该版本尚未发布，直接并入，不另开版本）
> 关联：011 US2（供应商分组 + 全局 200 上限）、018 US5（折叠 / `visibleFlat` 索引空间 / 搜索强制展开）、017（模型目录刷新与 TTL）、013（认证面板 42 个内置 provider）

## 需求拆解：五句话 → 五条款

| # | 用户原话 | 现状（018 之后） | 本 spec 的处置 |
|---|---|---|---|
| 1 | 可按供应商折叠 | ✅ 已实现：点组标题折叠、localStorage 记忆、当前组自动展开 | 不改（回归项） |
| 2 | **供应商标题居左** | ❌ **分组标题名称实际居中**（Bug） | **修复**，见 US2 |
| 3 | **搜索结果也要折叠** | ❌ 018 明确「搜索时强制全展开」 | **推翻 018 该条**，见 US3 |
| 4 | **最多展示 50 个供应商** | ❌ 无供应商数量上限 | **新增**，见 US1 |
| 5 | **每家模型数动态上限（<5 家时 200，多了递减，最少 5）** | ❌ 只有全局 200，一家大供应商就能把小供应商整组挤掉 | **新增**，见 US1 |

用户补充的关键前提（2026-11-10）：「实际上，每家的数量并不是确定的，有可能就一个，有可能几个，有可能十几个，有可能上百个。」—— 因此方案**不做总量守恒的跨组配额搬运**，见 D2。

## 现状与根因

### 根因 1：标题居中（视觉 Bug，已确证）

`styles.css:1189-1201` 的 `.model-group-title` 是 `display:flex` + `justify-content:space-between`，但 018 加折叠后该行有**三个**子元素：chevron `Icon`、`.model-group-name`、`.model-group-count`。`space-between` 在三个子项上会把中间项放在中线附近 —— 于是 chevron 贴左、**名称居中**、计数贴右。

修复方式（最小改动，不重排结构）：标题改 `justify-content: flex-start`，`.model-group-name` 给 `flex: 1 1 auto` + `text-align: left`（吃掉中间空白、从左侧起排），`.model-group-count` 给 `margin-left: auto`（仍贴右端，计数列对齐不丢）。

### 根因 2：上限是「全局 200」而不是「每家 200」

`modelGroups.ts:118-140` 的 `flattenGroups(groups, cap)` 按组顺序累加，凑满 200 条即停止，后续组一条都不渲染：

- 实测目录 359 条 / 2 家（openrouter 355 + 自定义 xiami 4）。当前顺序下 openrouter 吃掉 200 条配额，xiami 只剩 155 条余量 —— 眼下恰好够，但**再加一家 200 条以上的供应商，排在后面的小供应商会整组消失**（组标题都没了，用户以为没配置成功）。
- 「当前组置顶」（011 FR-007）只保住了当前模型所在组，其余组无保护。

改为「每家各自封顶」后，一家再大也不会挤掉别人。

### 根因 3：搜索强制全展开

`ModelPicker.tsx:72-77` 传 `keywords.length > 0 ? null : collapsed`，即有关键词时忽略折叠集合。018 的理由是「搜到了却看不见」，但用户现在希望搜索结果**保持分组结构且可折叠**（供应商多时，搜索结果仍可能很长）。

## User Stories

### US1 每家模型数量上限 + 供应商数量上限

- **供应商上限**：最多渲染 `50` 个分组。取序 = 当前模型所在组置顶（011 既有语义）+ 其余按 pi 原序；第 51 个及以后的分组不渲染条目也**不渲染标题**，在列表末尾给出一行提示「还有 N 个供应商，请缩小筛选范围」。
- **每家上限**：`P(n) = clamp(floor(1000 / n), 5, 200)`，`n` = **实际渲染的分组数**（即 `min(实际供应商数, 50)`，含空 provider 兜底组）。
  - `n ≤ 5` → `P = 200`（用户口径「少于 5 个时每家最多 200」；`n=5` 时为 200，阈值处连续，无突变）
  - `n = 10` → 100；`n = 20` → 50；`n = 50` → 20
  - 分母 `1000` 是可配置常量 `GROUP_BASE_BUDGET`，单点可调（见 Q1）
- **按需截断**：每家取 `min(该家实际条数, P)`。小供应商（1 个、3 个）按实际数量显示，**省下的配额不回填给大供应商**。总量上界 `n × P ≈ 1000`，真实分布下通常远低于此（多数供应商只有个位数模型）。

### US2 组标题左对齐

- chevron 在最左，名称紧贴 chevron 右侧从左起排，计数仍在行尾（`.model-group-count` 靠 `margin-left:auto` 贴右）。
- 长供应商名超宽时截断省略（`overflow:hidden; text-overflow:ellipsis`），不得把计数推出可视区。
- 折叠态与展开态标题几何一致（折叠只是隐藏条目，不改变标题排版）。

### US3 搜索态可折叠

- 推翻 018 的「搜索强制全展开」：关键词非空时**同样按分组渲染，且组标题可点击折叠**。
- 默认态：搜索开始时所有组默认**展开**（不沿用无搜索时的折叠记忆 —— 否则会出现「搜到了却在折叠组里看不见」，018 的原始顾虑仍然成立）。
- 搜索态的折叠是**临时状态**：不写 localStorage、不影响无搜索时的记忆；清空关键词或重新打开选择器即重置。
- 搜索态下 US1 的两个上限同样生效（50 个供应商 / 每家 P 条），否则「搜索一展开就渲染几百条」会把本条的收益抵消掉。

### US4 当前模型必须始终可达

- 当前模型所在组不因 50 上限被裁掉（置顶已保证）。
- 当前模型若因**组内截断**落在 `P` 之外（如 openrouter 355 条、当前模型是第 300 条），必须**进入渲染集合**：从该组截断序列中挤出最后一个槽位，把当前模型插在组首（去重，不重复渲染）。否则打开选择器定位不到当前模型，等于回归 011 US1 的修复目标。

### US5 截断必须可见

- 组标题计数改为 `已显示/总数`（如 `200/355`）；显示数等于总数时只显示总数（保持现状观感，如 `4`）。
- 发生组内截断的组，在组末追加一行「还有 N 个 —— 请缩小筛选范围」（`N = 总数 - 已显示`）。
- 被 50 上限挡掉的供应商，在列表末尾追加一行「还有 N 个供应商 —— 请缩小筛选范围」，与组内提示分属不同层级，不重复计数。
- 所有提示文案走 i18n 双份字典，不硬编码。

## 设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | `n` 取「实际渲染的分组数」而非原始供应商数 | 50 上限之后 P 才有意义；否则 200 家供应商会把 P 压到下限 5，而列表只渲染 50 家，白白变紧 |
| D2 | **不做总量守恒**：每家独立 `min(count, P)`，配额不跨组搬运 | 用户明确指出分布极不均（1 个 / 几个 / 上百个混杂）。守恒模型必须按权重分配，而权重一旦以「模型数」为准就退化成「大供应商吃掉大头、小供应商被挤掉」，正是要修的毛病 |
| D3 | 基准取 1000（`n=5` 时每家 200），而不是 200 | 若基准取 200，`n` 从 4 家变 5 家时每家上限从 200 骤降到 40，体验断崖；1000 让阈值处连续（`n≤5` 都是 200） |
| D4 | 每家下限 5，而上限 200 | 用户口径「最少的限制卡在至少 5 个」；200 与 011 既有上限一致，大供应商的观感与现在持平 |
| D5 | 供应商上限 50，**搜索态同样只在前 50 组内检索** | 用户 2026-11-10 明确选择。代价：排在第 51 名之后的供应商搜不到 —— 用末尾提示「还有 N 个供应商」作为可见反馈，并写进已知限制 |
| D6 | 搜索态折叠为临时状态，不落盘 | 搜索时的折叠意图是「这次先收起」，不代表长期偏好；落盘会让下次无搜索的视图莫名缺组 |
| D7 | 截断计算与折叠状态**解耦**（cap 只按组数算，不看谁折了） | 若折叠组不占配额，展开它会把别家挤掉，列表长度随交互抖动；解耦后展开某组只是显示它已截断后的那 P 条 |
| D8 | 空 provider 兜底组参与 `n` 计数与 `P` 分配 | 它是一个真实渲染的分组，把它排除会让 `n` 与渲染组数不一致 |
| D9 | 不引入虚拟列表 | 沿 011 Non-goal。折叠组零条目渲染已是主要收敛手段；1000 行上界作为已知风险记录（见 Q1 的降级路径） |
| D10 | `buildPickerData` 的第 4 参从位置参数 `cap` 改为 options 对象 | 上限维度从一个变成三个（供应商数 / 每家基准 / 每家上下限），位置参数会失去可读性；options 也便于测试单点覆盖 |

## 数值表（实现与测试的共同事实源）

`n` = 渲染分组数，`P = clamp(floor(1000 / n), 5, 200)`：

| n | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 | 12 | 15 | 20 | 25 | 30 | 40 | 50 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| P | 200 | 200 | 200 | 200 | 200 | 166 | 125 | 100 | 83 | 66 | 50 | 40 | 33 | 25 | 20 |
| 总量上界 | 200 | 400 | 600 | 800 | 1000 | 996 | 1000 | 1000 | 996 | 990 | 1000 | 1000 | 990 | 1000 | 1000 |

边界：`n = 0`（无模型）→ 不渲染，`P` 取 200 防御除零。

## 场景示例

| 场景 | 输入 | 结果 |
|---|---|---|
| A 真实现状 | 2 家：openrouter 355、xiami 4 | `n=2 → P=200`：openrouter 显示 `200/355` + 组末「还有 155 个」；xiami 显示 `4`（完整） |
| B 小供应商不被挤掉 | 3 家：A 355、B 200、C 4 | `P=200`：A `200/355`、B `200`（完整）、C `4` —— C 不再因 A 吃满全局配额而消失 |
| C 多家但每家都不大 | 10 家，各 40 条 | `P=100`：全部完整显示，无截断、无提示（不守恒模型的价值：不为凑总量而砍） |
| D 多家且每家都大 | 20 家，各 100 条 | `P=50`：每家 `50/100` + 组末「还有 50 个」，共 20 组 1000 条 |
| E 供应商超上限 | 60 家，各 30 条 | 渲染 50 组，`P=20`：每家 `20/30`；末尾「还有 10 个供应商」 |
| F 当前模型被截断 | 1 家 355 条，当前模型为第 300 条 | `P=200`，当前模型插在组首并高亮；打开即可见（US4） |
| G 搜索态折叠 | 20 家 fixture，输入关键词命中 5 家 | 5 组默认展开，可逐组折叠；清空关键词后恢复无搜索时的记忆折叠态 |

## 接口契约（实现依据）

`web/src/lib/modelGroups.ts`：

```ts
export const PROVIDER_LIMIT = 50;        // 供应商渲染上限
export const GROUP_BASE_BUDGET = 1000;   // 每家上限的基准（n≤5 时得 200）
export const GROUP_CAP_MAX = 200;        // 每家上限天花板
export const GROUP_CAP_MIN = 5;          // 每家上限地板

export function groupCap(providerCount: number): number;   // P(n)

export function buildPickerData(
  models: ModelInfo[],
  current: { provider: string; id: string } | null,
  keywords: string[],
  opts?: {
    collapsed?: ReadonlySet<string> | null;  // 生效的折叠集合（搜索态传临时集合）
    providerLimit?: number;
    baseBudget?: number;
    capMax?: number;
    capMin?: number;
  },
): PickerModelData;
```

`PickerModelData` 增改字段：

- `ModelGroup` 增 `total` / `shown` / `hidden`（`hidden = total - shown`）。
- `hiddenProviders: number`（被 50 上限挡掉的供应商数）。
- 原 `hidden`（全局）删除；组内隐藏量改从 `groups[].hidden` 取。
- `flat` / `visibleFlat` / `activeFlatIndex` 语义不变（`visibleFlat` 仍是高亮/键盘/定位的唯一索引空间）。

## 非目标

- 虚拟列表 / 窗口化渲染（沿 011）。
- 跨组配额搬运、按模型数给供应商加权排序、按相关性给搜索排序。
- 供应商字母序重排（一律 pi 原序，当前组置顶）。
- 折叠状态进 store / 桥接 / 跨设备同步。
- 供应商数量超过 50 时的「展开全部」按钮（用户的 50 上限是硬性的，不给绕过入口）。
- 组内截断后的「展开这家全部」按钮（筛选是唯一展开手段，见 US5 提示文案）。

## 验收口径

**纯函数（vitest）**
- `groupCap` 与数值表逐项一致（1…50，含 0 与超界防御）。
- 20 家 × 100 条 → 每组 `shown=50 / hidden=50`；扁平条目 = 1000。
- 55 家 × 3 条 → 渲染 50 组、`hiddenProviders=5`、每组 `shown=3`。
- 当前模型被组内截断时进入渲染集合且排在组首，`activeFlatIndex` 非 null。
- 折叠集合与截断组合：折叠组不进 `visibleFlat`，但其 `shown/hidden` 不变（D7）。
- 搜索态传临时折叠集合时行为与无搜索一致（不再有「强制展开」分支）。

**组件（playwright）**
- 组标题几何：名称左边界距标题左内边距 ≤ 60px（修复前居中约 150px+），计数右边界距标题右内边距 ≤ 16px。
- 组标题计数在截断时显示 `shown/total`，未截断时显示单一数字。
- 组末提示与末尾供应商提示的文本与数量正确（fixture 驱动）。
- 搜索后点组标题可折叠、可再展开；清空关键词恢复记忆折叠态。
- 折叠/展开不改变其他组的条目数（D7 无抖动）。

**真机**
- 真实目录（2 家 359 条）：openrouter 显示 `200/355` + 「还有 155 个」，xiami 4 条完整可见；打开即定位到当前模型。
- 折叠 openrouter 后重开选择器，折叠态保持；搜索某模型 id 命中后仍在对应组内可见。

**回归面**
- `model-picker.spec.ts` 既有折叠用例（018：折叠后键盘跳过、搜索展开、当前组自动展开、localStorage 记忆）按新语义复核 —— 其中「搜索强制展开」一条**改写**为「搜索默认为展开且可折叠」。
- 011 的三条交互（打开定位、分组、点外部关闭）零变化。
- 017 的 TTL 刷新、`sources.models` 状态、诊断面板零变化。

## 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 1000 行 DOM 在低配机打开偏慢 | 打开选择器首帧 | 折叠组零条目渲染；计算全在 `useMemo`；若真机实测卡顿，把 `GROUP_BASE_BUDGET` 降到 500（`n=5` 时每家 100），单点常量，一处改完 |
| 50 上限后搜索不到第 51 名之后的供应商（D5，用户明确选择） | 极端配置下的可发现性 | 末尾「还有 N 个供应商」提示；需要时可在后续版本改为「搜索不受 50 限制」，只需放开 `providerLimit` 在搜索态的传参 |
| 组内截断后当前模型被插到组首，与 pi 原序不一致 | 该组条目顺序不再是纯原序 | 仅对当前模型做一次置换，其余保持原序；`data-model-key` 去重保证不重复渲染 |

## 开放问题

- **Q1（不阻塞）**：`GROUP_BASE_BUDGET` 取 1000 还是 500。1000 与用户「少于 5 家每家 200」在阈值处连续，但极端场景渲染 1000 行；500 更保守（`n=5` → 每家 100）。默认按 1000 实现，真机手感不佳时改常量即可，不需要改结构。
- **Q2（不阻塞）**：供应商上限 50 是否需要「输错关键词也搜不到」的额外提示（例如搜索无结果时区分「无匹配」与「匹配项在第 51 名之后」）。默认不做，避免提示文案膨胀；如需要，后续在空态里加一行次级说明。
