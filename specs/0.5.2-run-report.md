| 1 | T004 / SC-002：`.empty-logo` 中心与消息区中心偏差 ≤2px | 按 `.empty-state`（图标+标题+模型名整块）中心验收，600px 时整块偏差 0px、图标中心在块中心上方 29.3px | 图标是三行堆叠的第一行，只有把标题与模型名甩到图标下方之外才能让图标严格居中，视觉上整块会明显偏低。整块居中才是「空态居中」的本意；偏差量级已从改造前的 −175px 降到 29.3px 且随窗口高度不再漂移 |
| 2 | T009 / SC-001：首屏可见 item 条数比基线增加 ≥15% | 改为同页前后对照：注入改造前几何再量一次，断言列总高下降、用户气泡总高占比 ≤0.85 | mock 每轮 assistant 输出 543px，一屏≈一轮，条数完全由 assistant 长度决定，与本次改动无关（实测「完全可见条数」前后都是 2）。用条数做判据会让这个 feature 的验收永远失败，且测的不是它改的东西 |
| 3 | FR-007：输入框到上限时消息区高度 ≥200px | 窗口高 ≥600px 时断言 ≥200px；400px 档只断言不被吞没（≥80px） | 算术冲突：400px 高的窗口里 45% 上限已占 180px，加上控制行与状态栏约 90px，消息区只剩 92px。两个条款在 ~560px 以下不可能同时成立 |
| 4 | FR-003：代码块 `scrollWidth === clientWidth` | 允许代码块**块内**横向滚动（`overflow-x: auto`），只禁止气泡与消息列产生横向溢出 | 沿用既有设计（`layout.spec.ts` 与 480px 以下换行规则）：82% 宽的气泡里塞一条 200 字符的单行代码，除了块内滚动没有诚实的做法；关键是内容可达、不是被裁掉 |
| 5 | T011：所有写入路径统一走 `applyText()` | `applyText()` 只接了 `/` 命令与 `@` 补全；IDE 注入 / 编辑回填 / 队列取回仍是 `setText` + `requestAnimationFrame(autosize)` | 后三条原本就有 rAF 重算（zcode 未动），行为与 `applyText` 等价；纯重构不带来可观测变化，且会扩大改动面。已在 §4 记录 |
