### 交付过程中自查出的三个追加缺陷

这三条不在最初的 8 条里，是复验过程中发现并当轮修掉的，一并留痕：

| 缺陷 | 现象 | 根因 | 修复 |

| #9 高并发退化 | 编辑后仍偶发整项目刷新 | 飞行中工具调用的参数容器用 `HashMap`，淘汰取 `keys.first()` 是哈希序不是插入序 → 淘汰了还在飞行的调用，它结束时找不到参数 → 降级成整项目刷新 | 改为先进先出（`VfsRefresh.InFlightToolArgs`），抽成纯类可单测 |

| #8 同文案连带误删 | 连发两条一样插话，取回一条把另一条也抹掉 | 撤回用 `filter` 删所有同文案条目 | 改为恰好删一条（`dropOneSteerCopy`） |

### 版本位（发版阻塞项）

`build.gradle.kts` 原本停在 `version = "0.5.10"`，而 0.5.10 已于 2026-11-25 发版并合入 main
（`origin/main` HEAD = 「merge: release/0.5.10 → main（0.5.10 发版）」，且它是本线 HEAD 的祖先）。
仓库约定「已发布号不复用」。更硬的理由是 `collectChangelog` 的写入段名取自 `project.version`
（`build.gradle.kts` 里 `val section = StringBuilder("## $pluginVersion — $date")`），不先进位就会写进
`## 0.5.10` 段、与 CHANGELOG.md 已有段冲突并被中止。

已进位到 **0.5.11**。`plugin.xml` 没有 `<version>` 标签，版本由 IntelliJ Platform Gradle 插件从
`project.version` 注入，所以 `build.gradle.kts` 是唯一真源。
