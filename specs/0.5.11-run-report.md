### 060 预览编辑器缺陷修复批（2026-11-20，分支 release/0.5.10-browser-build）

**输入**：搭 `release/0.5.10-browser-build` 工作树做 0.5.10 构建分支，安装到 IDEA 2026.2.3 真机复验时，连续撞出两个预览编辑器缺陷。

**缺陷 1 —— getFile() 未覆写（commit d4ccf97）**
PiBrowserFileEditor 实现 FileEditor 时漏了 getFile()，沿用平台被废弃的默认实现：IDEA 262 每次 EditorChange 记 SEVERE("must override it") 并把 null 传给 MessageBusImpl("getFile() returned null")，真机日志成片刷屏（09:41 旧会话实证）。修复 = 覆写 `getFile(): VirtualFile = file`。单测不能实例化编辑器（构造即建 JBCefBrowser），改为反射断言该方法由本类声明且非 synthetic 桥接——修复前 2 红、修复后 2 绿。

**缺陷 2 —— 预览快照在响应后被删（commit d556aad）**
LocalUiServer.servePreview 写完响应后 `Files.deleteIfExists(file)`，与 PiBrowserPreviews 的约定直接冲突：注册表注释写明 060 修订后 token 在 TTL 内**可重复取用**（面板 RELOAD 会重新请求同一 URL），但删除发生在服务端，注册表自己的单测看不见。真机证据 10:51:30 `preview serve failed` + `UI request failed: /preview/<token>`：首屏能渲染是因为第一次请求成功，第二次拿不到文件 → 404，两个请求并发时先取到路径再被另一个删掉 → 500。修复 = 文件生命周期归注册表（新增 serve(token) 只读字节不消费注册；clearExpired() 过期注册连同文件一起删），服务端只写字节、不再接触路径。

**顺带修掉的构建缺陷（commit b8a8e84）**
`generateBuildInfo` 只声明 outputs.dir 没声明 inputs，Gradle 首次构建后永远判它 UP-TO-DATE，jar 里的 commit id 冻结在旧提交上（真机现象：修完 getFile() 重建，产物仍写 commitId=20b0137）。照 buildWebUi 既有口径补 `outputs.upToDateWhen { false }`，重建后产物 commitId 与 HEAD 严格一致。

### 063 面板异常不崩溃 / 不空白批（2026-11-20，分支 release/0.5.10-browser-build）

**输入**：用户报「异常之后插件空白了，能否优化到，出现异常插件不要崩溃还能用」；前一批（062）报「健壮性需要提升」。

3. **重建风暴（自激）**：`CloseGuard.contentRemoved` → `recreateIfLast` 在 IDE 关闭期 12 秒内触发 11 次（13:35:29.933 → 13:35:41.140），每次新建一个 `JBCefBrowser`。同样的风暴在 2026-11-18 12:05（17 秒 5 次）、2026-11-19 05:21（4 次）也出现过 → 它是自激循环，不是单纯的关机噪声
4. **异常击穿漏斗**：062 的 `BrowserSafety.guard` 只 catch `Exception`；平台在原生对端已死时会抛 `Error` 子类（如 `NoClassDefFoundError`），它直接穿过漏斗打到 EDT——这正是「IDE 内部错误」弹窗的来源
5. **面板没有可观测状态**：`showFailure()` 只覆盖 JCEF 不可用 / 加载失败 / 创建失败；「浏览器起来了但永不绘制」这条路径没有任何可见状态 → 用户只看到一片空白
