# Feature Specification: 自动编辑后不闪、不夺走输入焦点

**Feature Branch**: `[20261127-214747-repaint-focus]`
**Created**: 2026-11-27
**Status**: 草稿（待实现）

**GitHub Issue**: [#9](https://github.com/57ggfk/pi-agent-idea/issues/9)

**Input**: 用户报缺陷——「自动编辑完文件触发 IDE 刷新 UI 会闪一下导致输入框失去焦点，
影响正在输入消息」

## 背景

pi 自动改完文件后，IDE 侧会触发一次刷新（VFS 刷新 + 前端的重绘请求）。
这条链路上有一个**强制整帧重绘**，它会让 webview 失焦 → composer 的 textarea 失焦 →
用户正在敲的字进了黑洞。

## 用户场景与验收

### User Story 1 — 正在打字时 pi 改文件，不丢字（Priority: P1）

**为什么重要**：这是「一边让 agent 干活、一边自己写需求」这个并行动作的核心。
失焦一次，用户已经敲的半句话就没了——而且失焦原因完全不可见（画面只是闪一下）。

**独立可测**：pi 跑着 → 在输入框里打字 → 让 pi 改一个文件 → 输入框仍聚焦，
已打的字还在，光标还在原处。

**验收场景**：

1. **Given** 输入框有焦点且已输入若干字符，**When** pi 编辑完文件触发刷新，
   **Then** 输入框**仍然聚焦**，字符一个不少，光标位置不变
2. **Given** 同上，**When** 刷新完成，**Then** 画面**不闪**（没有整帧重绘）
3. **Given** 输入框**没有**焦点（用户在看别处），**When** pi 编辑完文件，
   **Then** 行为与今天一致（不抢焦点）

### User Story 2 — 该刷的地方还是刷得对（Priority: P1）

**为什么重要**：整帧重绘当初是为了治「OSR 帧残留」——切视图后屏幕上留着上一个视图的
残影，几十秒不消失（0.5.4 真机）。**不能为了不闪而把那个 bug 放回来**。

**验收场景**：

1. **Given** 用户在聊天页与管理页之间切换，**When** 切换完成，
   **Then** 屏幕上**没有**上一个视图的残影（该重绘的地方仍然重绘）
2. **Given** 一条大消息（几千字）插入消息流，**When** 渲染完成，
   **Then** 画面正确（不残留、不半截）

## 需求（Functional Requirements）

- **FR-001**：输入框有焦点时，任何 IDE→前端的刷新都**不得**夺走焦点。
- **FR-002**：任何 IDE→前端的刷新都**不得**清掉输入框里的内容或移动光标。
- **FR-003**：**非视图级**的刷新（文件内容变化、状态更新）**不得**触发整帧重绘。
- **FR-004**：**视图级**的切换（换 tab、换子面板、大 DOM 替换）**仍要**整帧重绘，
  不得让 OSR 帧残影回来。
- **FR-005**：重绘后若焦点确实需要恢复，必须恢复到**同一个 textarea 的同一光标位置**。

## 关键设计取舍（待拍板）

- **「焦点归谁管」**：
  - 候选 A：前端记「textarea 是否有焦点」，重绘后由前端自己恢复
  - 候选 B：IDE 侧在重绘前问前端「焦点在哪」，重绘后按答案恢复
  - 候选 C：**不恢复**，而是**根本不做会失焦的事**——把「视图级重绘」限定在
    「确实换了视图」的时刻，其余一律不做
  - C 最干净：**问题根本是「不该重绘的时候重绘了」**。改文件根本不是视图切换，
    为什么要整帧重绘？→ FR-003 就是这个意思。
- **哪些路径该重绘**：现有的 `requestRepaint()` 调用点要逐个审：
  `App.tsx`（切 tab）、`ManageView.tsx`（进管理页 / 切子 tab）、`store.ts`
  （切会话 / 新会话）。**这些确实都是视图级** → 保留。
  而「pi 改完文件」这条路径上，如果也有 `requestRepaint()`，那是误用 → 去掉。
- **失焦的另一半**：即使不整帧重绘，JCEF 的 `wasResized` 反射调用本身也可能触发
  焦点变化 → 要实测确认「去掉重绘」是否足以解决，还是还要补焦点恢复。

## 非目标

- 不改 OSR 帧残留的既有修法（那是有效的）。
- 不做「刷新后自动把焦点抢回输入框」——那是另一种干扰。

## 边界与风险

- **整帧重绘是 0.5.4 为治真机 bug 引入的**（`JcefFrameRepaint`），删错了会把
  「视图切换后残影」放回来——这是本批最需要真机确认的一条。
- **JCEF 的焦点行为**：整帧重绘到底会不会让 textarea 失焦，需要真机量；
  也不能排除是「重绘 + React 重渲染」的组合效应。

## 假设与依赖

- `JcefFrameRepaint.forceRepaint` 是唯一的整帧重绘入口（反射调 CEF 的 `wasResized`）。
- `web/src/lib/repaint.ts` 的 `requestRepaint()` 是前端唯一的重绘请求入口。
