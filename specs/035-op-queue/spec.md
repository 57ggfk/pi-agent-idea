# Feature Specification: 管理操作串行队列

**Feature Branch**: `release/0.5.9-20261114`

**Created**: 2026-11-14

**Status**: Approved（2026-11-14 用户拍板立项 C1；设计要点 Q1–Q2 按推荐默认）

**Input**: 034 验收讨论中用户问「如果支持多个操作会怎么样」——单飞互斥下点击被禁用；
并发又会撞两把无锁写（`<agent>/npm` 与 settings.json）。队列是安全解。

**可行性结论**：前端串行队列即可——后端 RPC 本身无状态，把「一次一个」从 UI 禁用
改为**客户端排队逐个执行**，点击不再被禁，排队态可见。

## User Scenarios & Testing

### US1 - 点击即排队 (P1)
对技能/包行连点多个操作（如 A 卸载、B 安装、C 升级）：按钮不再禁用，点击立即入队；
行上显示「排队中（第 N 位）」，队首行显示进行中状态（沿用现有进度线）。

### US2 - 逐个执行、互不干扰 (P1)
队列 FIFO 逐个执行；前一个完成后横幅显示其结果，下一个自动开始；失败的项不影响
后续项继续执行（横幅保留最后一个结果，失败详情可展开）。

### US3 - 跨面板共享队列 (P1)
技能面板与包面板（含市场一键安装）共用同一条队列——它们写同一批文件
（settings.json / agent npm 目录），必须全局串行；跨面板操作同样可见排队态。

## Requirements

- **FR-001** 包与技能的全部**变更型**操作（install/remove/upgrade/updateAll/reinstall、
  skillSetEnabled/skillToggleModelInvocation/skillSetSourceEnabled）MUST 经共享串行队列执行；
  只读操作（list/检测版本/刷新）不排队。
- **FR-002** 入队后源操作按钮 MUST NOT 再禁用本行的入队路径（同键重复入队去重）；
  排队/进行中的行显示状态徽章（排队中（第 N 位）/进行中）。
- **FR-003** 队列 MUST FIFO；一项失败（ok:false 或异常）MUST 记录结果并继续下一项。
- **FR-004** 结果横幅展示**最后完成**的一项；进行中/排队中状态 MUST 实时可见。
- **FR-005** 市场一键安装 MUST 入同一队列；安装完成刷新已装列表后，市场卡片「已安装」态自动更新。
- **FR-006** 刷新（list 类读操作）MUST NOT 入队，可随时执行。

## Decisions

| # | 决定 |
|---|---|
| Q1 | 队列粒度 = 全局单队列（技能+包共用，串行最安全）；按面板分队列反而失去互斥意义 |
| Q2 | 失败重试 = 本轮不做自动重试；横幅+详情已可见，用户手动重试（再次点击即重新入队） |

## 不做的事

- 不做取消队列/清空队列（每项耗时短，预检已防长挂起；真需求再立项）
- 不做跨类操作合并（如批量安装打包）
- MCP/auth 操作不进队列（写的是不同文件，且历史行为一直单飞）

## 验证计划

实现后填写（e2e：`?pkgspeed=slow` 下双操作排队顺序断言；单测：队列 FIFO/失败续跑/去重）。
