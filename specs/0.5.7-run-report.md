## 过程中的判断与偏差（必须知道的几条）

1. **022 的 `content-visibility` 换位置**：原 task 把它加在 `.item` 上，而 `content-visibility: auto` 自带 paint containment，会把悬在消息**上边缘之上**的动作工具条裁掉一半——上半截既不绘制也不响应点击，`elementFromPoint` 落到 `.message-col`。这是 022（未发布）里的真实回归，023 的 e2e 第一次真正**点击** Fork 时才暴露（`message-fork.spec.ts` 6 例全红，报 `«div class="message-col"» intercepts pointer events`）。修法：两条声明移到 `.item-body`，工具条不再被裁，收益（长会话不逐帧重绘）不变。已在 022 `tasks.md` 的 T410 里留痕。
2. **e2e 定位收紧，没有放宽**：`forkAt()` 的语义从「assistant 序号」改为「第几轮」，配 `REPLIES_PER_ROUND = 2` 与 `roundEndReply()`（mock 一轮固定两条 pi 回复）。既有 4 处 `.first()` 逐条改到本轮末尾（`confirm.spec.ts` 用 `.last()`、`sessions.spec.ts` 用 `nth(1)`、`session-search.spec.ts` 本来就是 `.last()`），**没有**任何一处改成 `count > 0` 之类模糊断言。
3. **021 的失败文案复用既有 key**：`session.switchFailed` 没有新增，用的是 `error.switchSession.failed`（T310 的同义落地），避免同一件事两套字符串。
4. **023 T514 探针**：插话（steer）在 pi 侧就是一条真实 user entry，store 单测用「q1 → 工具回复 → steer → 回复 → q2」验证分支点会数到插话（选中 `entry-3 = q2`，不切在 steer 前面）。真机插话行为仍待目验。
5. **020 的 `long` 夹具语义变了**：按组截断后 mock 的 `?picker=long` 从「1 + 204 两组」变成「每组 200、共 201 行」，e2e 断言同步改写（`200/204` + 组末 4 条），不是放宽阈值。
