## 5. 025 测试证据（2026-11-12 凌晨基线）

| 套件 | 结果 | 基线变化 |
|---|---|---|
| `npm run typecheck` | 0 错误 | — |
| `npx vitest run` | **406/406** | 新增 autosizeAndReveal 2 条（plain-object textarea 断言赋值顺序契约） |
| `npx playwright test` | **306/306**（修复后终轮） | 新增 composer-inject-autosize 4 条（数值断言：height===cap、scrollTop+clientHeight≥scrollHeight-1、caret===value.length）；stress ×5 轮稳定 |

**实现要点**：`autosizeAndReveal` = autosize + 同帧 `scrollTop=scrollHeight`；收口 effect 等待
「已提交 value 长度 === 期望长度」再测量（updater 里捕获期望值，effect 体同步种下 `-1` 哨兵）——
这一步修掉了**实测复现的根因级竞态**：React 18 并发渲染会把 quote 的 updater 推迟到首个 rAF
**之后**执行，settle 读到旧值（12 字符 / 38px）且 `expected` 还是 null，直接按过期值收口，之后
再无重测——这正是用户「时好时坏」的完整机理（探针证据：`note len=168` 出现在 `settle` 日志之后）。
可疑测量判据放宽为「`style.height < clampComposerHeight(scrollHeight, appHeight) - 1`」（覆盖 38px
这类非 floor 的过期值与 0 高度布局两种形态）；`.app` ResizeObserver 恢复时一次性
autosizeAndReveal 并清标记；普通重测（字体加载、窗口缩放）保持裸 autosize，绝不滚动（US4）。
e2e 备忘：playwright 的 loader 不接受 `import("@playwright/test").Page` 内联类型导入（用顶层
`import type { Page }`）；消息工具条 hover 才可见（`visibility:hidden`），断言前先 hover。

| mock 新旋钮 | `?hang=cmd[:n]`（响应永久吞掉）、`?slowN=cmd:n:ms`（第 n 次调用延迟——boot 重放会吃掉 one-shot `?slow=`，US2 场景需按调用序号注入） | — |

**实现要点**（对应 spec 三层叠加缺陷）：① 超时在 store 侧 `withTimeout` 实现（jcef 360s 全局默认不动，
桥接层 5s 粒度太粗会破 8s 预算）；② FR-003 用 `startedAt` 身份判据清自己的 pending；
③ FR-004 接管 `kind:"history"`、保留 `kind:"new"` 去重（避免 pi 侧孤儿空会话）。
失败出口统一：清 pending → 回会话列表 → retry bar（`retrySwitch`）→ `switch.failed` 埋点
（reason=timeout/rpc/abort_timeout）。

**E2E 两个调试发现**（防复发备忘）：
- boot 时 `init()` 会 `get_messages` 重放转录 + `get_state`（Promise.all），one-shot `?slow=` 在
  场景开始前就被消费——按调用序号注入用 `?slowN=cmd:n:ms`；
- 真机「连点三次」的竞态等价物是**同一帧内同步派发两次 click**（第一次 dispatch 后 tab 已切走、
  列表已卸载），e2e 用一次 `page.evaluate` 双击复现。
