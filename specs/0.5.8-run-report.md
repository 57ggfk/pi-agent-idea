**实现要点**（对应 spec 三层叠加缺陷）：① 超时在 store 侧 `withTimeout` 实现（jcef 360s 全局默认不动，
桥接层 5s 粒度太粗会破 8s 预算）；② FR-003 用 `startedAt` 身份判据清自己的 pending；
③ FR-004 接管 `kind:"history"`、保留 `kind:"new"` 去重（避免 pi 侧孤儿空会话）。
失败出口统一：清 pending → 回会话列表 → retry bar（`retrySwitch`）→ `switch.failed` 埋点
（reason=timeout/rpc/abort_timeout）。

**E2E 两个调试发现**（防复发备忘）：
- boot 时 `init()` 会 `get_messages` 重放转录 + `get_state`（Promise.all），one-shot `?slow=` 在
  场景开始前就被消费——按调用序号注入用 `?slowN=cmd:n:ms`；
- 真机「连点三次」的竞态等价物是**同一帧内同步派发两次 click**（第一次 dispatch 后 tab 已切走、
  列表已卸载），e2e 用一次 `page.evaluate` 双击复现。
