# Feature Specification: 消息级操作（复制 / 引用 / 重新生成 / 编辑重发）

**Feature Branch**: `005-message-copy-actions`

**Created**: 2026-11-03

**Status**: Draft

**Input**: 用户需求：「用户消息和 pi 消息需要有复制等功能」。
经澄清确认：动作集 = 复制 + 引用到输入框 + 重新生成 Pi 回复 + 编辑并重发用户消息；
入口 = 悬停工具条；Pi 回复的复制格式 = Markdown 源。

## 问题陈述

消息列表里目前唯一的复制能力是**代码块**右上角的 Copy 按钮。用户想复制一段
Pi 的完整答复（贴给同事、贴进 issue、贴给另一个 AI 工具继续问）时，只能用鼠标
划选渲染后的文本——选中范围容易把代码块拷贝按钮、渲染残片一起带上，且完全
拿不到代码块围栏等 Markdown 结构；想复制自己发过的消息（复用一段精心写的
prompt）时同样只能划选。此外，对 Pi 答复不满意时没有任何「重来」手段，只能
手动把原话再打一遍；想基于某条回复继续追问时，也只能手动复制再粘贴到输入框。

| 操作 | 现状 |
|---|---|
| 复制整条消息 | 只能划选渲染后文本，Markdown 结构丢失 |
| 引用某条回复继续追问 | 手动复制 → 点输入框 → 粘贴 |
| 重新生成不满意的回复 | 无（只能重新手打请求） |
| 修改已发送的消息重问 | 无 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键复制任意消息 (Priority: P1)

用户想把某条消息的内容拿到 IDE 之外使用。把鼠标悬停在该消息上，出现操作条，
点击复制按钮后内容进入剪贴板，按钮给出短暂的成功反馈。

- 用户消息复制的是**原始文本**（用户输入了什么就是什么）；
- Pi 消息复制的是**Markdown 源**（text 块按顺序拼接）：代码块带 ``` 围栏、
  列表/粗体/链接保留标记；**不包含** thinking 块、工具调用卡片与图片数据；
- 错误消息（`item-error`）同样可复制——复制错误文本去搜索或提 bug 是高频场景。

**Why this priority**: 核心诉求，零协议风险，且已有代码块 Copy 的交互与剪贴板
降级先例可循，是最小可交付切片。

**Independent Test**: 悬停任一消息 → 点复制 → 读剪贴板，断言内容与该消息的
原始文本 / Markdown 源逐字符一致；按钮出现可见的成功反馈。

**Acceptance Scenarios**:

1. **Given** 一条含代码块与列表的 Pi 回复，**When** 悬停并点击复制，**Then**
   剪贴板内容为该回复的 Markdown 源（代码块带围栏、列表带 `-` 标记），
   不含 thinking 内容与工具调用信息。
2. **Given** 一条用户消息，**When** 悬停并点击复制，**Then** 剪贴板内容与
   发送时的原始输入逐字符一致（含换行）。
3. **Given** 一条错误消息，**When** 悬停并点击复制，**Then** 剪贴板内容为
   展示的错误文本。
4. **Given** 点击复制成功，**When** 观察按钮，**Then** 按钮出现≥1 秒的成功
   状态变化（如 ✓），随后自动恢复。
5. **Given** 宿主为 JCEF（无异步剪贴板 API），**When** 点击复制，**Then**
   剪贴板仍然写入成功（走既有降级通路），行为与浏览器环境无差异。

---

### User Story 2 - 引用消息到输入框 (Priority: P1)

用户想基于某条消息继续追问。悬停该消息点「引用」，该消息内容以引用形式
预填到底部输入框，焦点自动落入输入框，用户直接补充问题后发送。

**Why this priority**: 纯前端行为，成本低、追问频次高；与 US1 共享悬停
工具条，同批交付最自然。

**Independent Test**: 悬停消息 → 点引用 → 断言输入框出现引用预填文本、
焦点在输入框、原有草稿未被覆盖。

**Acceptance Scenarios**:

1. **Given** 输入框为空，**When** 对一条 Pi 回复点引用，**Then** 输入框预填
   该消息内容的引用形式（blockquote 样式），焦点位于输入框且光标在文本末尾。
2. **Given** 输入框已有未发送草稿，**When** 点引用，**Then** 草稿被保留，
   引用内容追加在其后（不得覆盖用户正在输入的内容）。
3. **Given** 对一条用户消息点引用，**Then** 行为与引用 Pi 回复一致
   （引用内容为该消息原始文本）。

---

### User Story 3 - 重新生成最后一条 Pi 回复 (Priority: P2)

用户对最后一条 Pi 回复不满意。悬停该回复点「重新生成」，旧的回复被移除，
插件基于同一份对话上下文重新请求，新回复以流式呈现。

**Why this priority**: 价值高但涉及会话协议（历史回滚 / 重放），风险与
工作量显著高于 US1/US2，排第二梯队。

**Independent Test**: 对最后一条 assistant 消息点重新生成 → 断言旧回复被
替换（非追加）、按既有流式路径重新渲染、会话上下文未丢失。

**Acceptance Scenarios**:

1. **Given** 会话处于空闲且最后一条是 assistant 消息，**When** 点重新生成，
   **Then** 旧回复从列表中移除，同位置开始流式渲染新的回复。
2. **Given** 重新生成进行中，**When** 观察操作条，**Then** 重新生成与编辑
   入口不可用（流式结束前不能再次触发，与 FR-010 一致）；历史消息的复制与
   引用是读操作，照常可用。
3. **Given** 重新生成请求失败，**When** 错误返回，**Then** 按 003 号规格的
   错误可见性要求展示（可见的错误消息，可复制——回到 US1 的场景）。
4. **Given** 最后一条消息是用户消息（Pi 尚未回复），**When** 悬停之前的
   assistant 消息，**Then** 重新生成按钮不出现（仅对最后一条 assistant
   消息提供；中间消息重生成会造成上下文分叉，超出本轮范围）。

---

### User Story 4 - 编辑并重发最后一条用户消息 (Priority: P2)

用户发现自己发出去的 prompt 有误或想换个问法。悬停**最后一条**用户消息点
「编辑」，消息内容回填输入框进入编辑态；发送后原消息被修改后的内容替换，
Pi 基于新内容重新回答（原 Pi 回复被替换）。

**Why this priority**: 与 US3 同属会话协议改动，价值相近；语义上依赖
「替换历史」的同一套能力，随 US3 一起排期实现成本最低。

**Independent Test**: 对最后一条 user 消息点编辑 → 输入框回填原文本 →
修改后发送 → 断言原消息内容被替换、原 Pi 回复被移除、新回复流式到达。

**Acceptance Scenarios**:

1. **Given** 最后一条是 user 消息且会话空闲，**When** 点编辑，**Then**
   输入框回填该消息原始文本（可编辑），发送按钮就绪。
2. **When** 编辑后发送，**Then** 消息列表中该用户消息的显示内容更新为新文本，
   其后的旧 Pi 回复被移除，新回复流式到达。
3. **Given** 用户点编辑后想放弃，**When** 清空输入框，**Then** 不对消息列表
   与待发送内容产生任何变更（发送按钮因空内容禁用）。
4. **Given** 目标用户消息不是最后一条，**When** 悬停，**Then** 编辑按钮不出现
   （理由同 US3 场景 4）。

---

### Edge Cases

- **流式中的消息**：流式未结束的 assistant 消息不出现操作条（内容在变，
  复制/引用/重生成均无稳定语义）；流式结束后操作条出现。
- **纯图片消息**（无任何 text 块）：复制与引用无内容可用，对应按钮隐藏
  （不显示一个点了没反应的按钮）。
- **thinking 展开态不影响复制**：复制内容固定为 Markdown 源，与 thinking
  块是否展开无关。
- **操作条不得改变布局**：工具条浮现不得引起消息位移、不得使消息列表出现
  横向滚动（`scrollWidth === clientWidth`），不得溢出 `.app` 容器（宪法 II/III）。
- **滚动中悬停**：消息列表随新消息自动滚到底时，悬停工具条跟随其消息，
  不得残留固定在旧位置。
- **重生成/编辑重发与并发输入**：重新生成进行中用户在输入框打字不受影响；
  但重新生成或编辑重发进行中，另一者的入口必须不可用（同一时刻只有一个
  「历史改写」类操作在途）。
- **空内容编辑**：编辑态下把文本清空后发送按钮禁用（不得发出空消息替换）。
- **剪贴板权限失败**（极少见）：复制失败时按钮反馈为失败态而非成功态，
  不静默假装成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每条 user / assistant 消息 MUST 在指针悬停时展示操作条；
  流式未结束的 assistant 消息与系统消息（`system-item`）除外。
- **FR-002**: 操作条 MUST 至少包含复制；对最后一条 assistant 消息额外提供
  重新生成，对最后一条 user 消息额外提供编辑；引用对所有 user / assistant
  消息提供（受 FR-007 内容可用性约束）。
- **FR-003**: 复制用户消息 MUST 写入其原始文本；复制 Pi 消息 MUST 写入其
  Markdown 源（text 块按顺序拼接，不含 thinking / 工具调用 / 图片数据）。
- **FR-004**: 复制成功 MUST 有≥1 秒的可见成功反馈；失败 MUST 有可区分的
  失败反馈，不得静默。
- **FR-005**: 复制 MUST 在无异步剪贴板 API 的 JCEF 环境下通过降级通路同样
  成功（行为级要求：真机复制可用）。
- **FR-006**: 引用 MUST 将消息内容以引用形式预填输入框：保留已有草稿、
  追加在草稿之后、焦点移入输入框。
- **FR-007**: 无 text 内容的纯图片消息 MUST 隐藏复制与引用按钮。
- **FR-008**: 重新生成 MUST 仅对最后一条 assistant 消息且会话空闲时可用；
  触发后 MUST 移除旧回复并基于既有上下文重新请求，新回复走既有流式渲染路径。
- **FR-009**: 编辑重发 MUST 仅对最后一条 user 消息且会话空闲时可用；发送后
  MUST 替换该消息文本、移除其后的旧 Pi 回复并触发重新请求。
- **FR-010**: 重新生成与编辑重发 MUST 互斥：任一在途时另一者不可触发。
- **FR-011**: 操作条 MUST 不改变消息列表几何：不引起消息位移、不产生横向
  滚动、完整落在 `.app` 容器内（四边界断言）。
- **FR-012**: 操作条上每个按钮 MUST 具备可访问名称（aria-label），图标纯
  视觉呈现。
- **FR-013**: 错误消息（`item-error`）的复制行为与普通消息一致（FR-003/004）。

### Key Entities

- **消息动作**（copy / quote / regenerate / edit）× **消息角色**（user /
  assistant）× **条件**（是否最后一条、会话是否空闲、是否有 text 内容、
  是否流式中）的**适用矩阵**——实现与测试均以此矩阵为准。
- **悬停操作条**：消息粒度浮现，按钮集按适用矩阵动态决定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 复制任意消息从「划选 + Ctrl+C（且丢失 Markdown 结构）」变为
  一次点击，e2e 可断言剪贴板内容与 Markdown 源逐字符一致。
- **SC-002**: 基于某条消息追问的操作从「复制→点输入框→粘贴」3 步降为 1 步，
  且焦点已就位可直接输入。
- **SC-003**: 对不满意的回复重问从「手动重打请求」变为一次点击且旧回复被
  正确替换（列表中不出现重复回答）。
- **SC-004**: 现有 e2e 几何断言套件扩展后全绿：操作条存在时不破坏任何既有
  布局断言（消息列表 `scrollWidth === clientWidth`、无 `.app` 溢出）。

## Assumptions

- **仅最后一条消息支持重新生成 / 编辑重发**：对历史中间消息做此类操作需要
  会话分叉能力，成本与语义复杂度不成比例，明确排除在本轮之外（US3/US4
  场景 4 已将此固化为可验收行为）。
- **引用格式**采用 Markdown blockquote（`> ` 前缀），具体拼接细节（多段、
  代码块的嵌套引用处理）在 plan 阶段定，验收只约束「输入框预填 + 草稿保留 +
  焦点」三个行为点。
- **重新生成 / 编辑重发的会话回滚实现方式**（截断重放 vs 整段重发）取决于
  pi RPC 协议能力，属 plan 阶段的技术决策；本规格只约束用户可见行为
  （旧回复移除、新回复流式、上下文不丢）。
- **复制为纯文本**（去除 Markdown 标记）本轮不做；如后续需要，作为操作条
  的扩展项另立规格。
- 键盘快捷键（如 Ctrl+Shift+C 复制当前悬停消息）不在本轮范围；操作条按钮
  保持可聚焦（FR-012）已为后续可达性留了接口。
