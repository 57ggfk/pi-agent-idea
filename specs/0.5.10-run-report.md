## 048 预览编辑器缺陷修复批（2026-11-20，分支 release/0.5.10-browser-build）

**缺陷 1 —— getFile() 未覆写（commit d4ccf97）**
PiBrowserFileEditor 实现 FileEditor 时漏了 getFile()，沿用平台被废弃的默认实现：IDEA 262 每次 EditorChange 记 SEVERE("must override it") 并把 null 传给 MessageBusImpl("getFile() returned null")，真机日志成片刷屏（09:41 旧会话实证）。修复 = 覆写 `getFile(): VirtualFile = file`。单测不能实例化编辑器（构造即建 JBCefBrowser），改为反射断言该方法由本类声明且非 synthetic 桥接——修复前 2 红、修复后 2 绿。

**缺陷 2 —— 预览快照在响应后被删（commit d556aad）**

## 050 浏览器失活健壮性批（2026-11-20，分支 release/0.5.10-browser-build）

- `PiBrowserKernel`：`LoadURL / reload / stopLoad / goBack / goForward / canGoBack / canGoForward / find / stopFinding / getURL / executeJavaScript / tap 注入 / openDevtools` 全部改走漏斗（`safe` / `safeFacade`）；新增 `disposed` 标志——内核释放后调用一律 no-op、`ensureCreated` 不再复活已释放的内核、`dispose()` 清空所有回调
- `BrowserPanel`：新增 `disposed` 标志，所有 EDT 回调先判活（状态 / 地址 / 标题 / 导航态 / 下载进度 / 下载完成 / 弹窗询问 / 页内查找）；`onStateChanged` 整体包进漏斗——平台意外降级为「工具条状态陈旧」，而不是 IDE 弹窗

## 051 面板异常不崩溃 / 不空白批（2026-11-20，分支 release/0.5.10-browser-build）

**输入**：用户报「异常之后插件空白了，能否优化到，出现异常插件不要崩溃还能用」；前一批（050）报「健壮性需要提升」。

**根因（idea.log 实证，不是猜测）**

1. **无限重建循环——空白的直接原因**：面板的崩溃保护是「60s 滑动窗口内最多 2 次重建」，而触发重建的静默阈值是 90s——**窗口比阈值还短**。每次重建都是自己窗口里的唯一一条记录，计数永远到不了上限；页面只要一直死着，面板就每 90 秒重建一次内嵌浏览器，永不停歇。日志实证：13:26:47 / 13:28:47 / 13:30:17 / 13:31:47 / 13:33:17 / 13:34:47 每 90 秒一条「Rebuilding Pi Agent UI (no bridge poll for 90s)」
2. **死亡页面被伪装成存活**：桥接按实例记住最后一次轮询，上一页的最后一次轮询会跨重建存活；旧代码直接拿「距上次轮询多久」比阈值，于是死页面看起来一直活着
3. **重建风暴（自激）**：`CloseGuard.contentRemoved` → `recreateIfLast` 在 IDE 关闭期 12 秒内触发 11 次（13:35:29.933 → 13:35:41.140），每次新建一个 `JBCefBrowser`。同样的风暴在 2026-11-18 12:05（17 秒 5 次）、2026-11-19 05:21（4 次）也出现过 → 它是自激循环，不是单纯的关机噪声
4. **异常击穿漏斗**：050 的 `BrowserSafety.guard` 只 catch `Exception`；平台在原生对端已死时会抛 `Error` 子类（如 `NoClassDefFoundError`），它直接穿过漏斗打到 EDT——这正是「IDE 内部错误」弹窗的来源
