# Feature Specification: 049 内置浏览器 P1（agent 融合 + 链接多选项）

**Feature Branch**: `release/0.5.10`

**Created**: 2026-11-18

**Status**: Draft — 048 P0（预览基座）之上的深化版。P0 已交付边界见 [048 spec](../048-in-app-browser-p0/spec.md)：地址栏页签/历史导航/本地 HTML 预览/外链三态/弹窗同视口接续/下载落盘/错误卡与崩溃自愈/编辑器呈现。本版不重做任何 P0 条目。

**Input**: 用户（2026-11-18 晚指令拆解）
> ① 竞品探索：主流产品内置浏览器该有什么功能，做矩阵对照 048 P0，列出该补什么、先补哪个；② 点击链接可选拥有内置浏览器打开；有多种目标就提供多个选项让用户明确选；外部浏览器 = 系统默认（行为不变）；与 US4 三态设置协调成简洁清晰的选择器，默认零变化；③ 融合进 agent：AI 自己决定什么时候打开内置浏览器（典型：AI 开发外部功能→起 web 服务→开内置浏览器访问验证→读回页面状态判断成功），研究 pi 工具调用机制找通信路径再实现，真机验证完整链路；④ 真实模拟用户操作走完整流程，站在正常人类用户角度确保可用/易用/简洁/美观。

### 该补什么、先补哪个（取舍理由）

1. **缺口 B（agent 驱动 + 读回状态）先补**——用户点名（任务 3），且是 Cursor/Codex 共有、我们完全缺失的最大差距；它把内置浏览器从「人看的预览」升级为「agent 的验证器官」，是 042 分层路线 P1 的核心。MVP 范围刻意收窄：`open / read / reload` 三个动作 + 文本级读回（title/url/innerText 摘录/加载状态），**不做**点击/输入/截图（Cursor 有但工程量大一个数量级，且截图回流需要前端图片渲染配合，留 P2）。
2. **缺口 A（外部打开按钮）随本轮顺手补**——Simple Browser 与 JetBrains 都有，用户在内置页签里跳完整浏览器的唯一现成途径是复制地址；实现成本一个按钮，收益直接。
3. **链接多选项选择器（任务 2）与 2 同属「打开渠道」主题**——竞品参照：VS Code 点外链弹「Open / Configure Trusted Domains / Cancel」三选项对话框（Ask 模式）；JetBrains 无 Ask。我们 P0 的 ASK 态是二值 Yes/No 模态框，无法承载「明确看到所有去向再选」的意图，本轮升级为多选项弹出菜单（详见 FR-1 取舍）。
4. **不补**（P2/P3，方向已记于 042）：console/network 进上下文（需 CDP 管道）、页面评论回流（Codex 独有，前端批注层）、DevTools 入口、多标签、页内查找、缩放、地址栏历史。

## 二、User Stories

### US1 - 链接点击多选项选择器 (P1)
用户在聊天里点击外链（设置 = 「每次询问」时）弹出一个轻量选择菜单，明确列出所有去向并选择：**在系统浏览器打开 / 在 Pi 内置浏览器打开 / 复制链接地址**（Esc 或点外关闭 = 不打开）。菜单是 JBPopup 非模态列表，键盘（↑↓/Enter）与鼠标均可操作。

**「多种选项 = 3 种」的取舍理由（用户指令授权本规格定夺）**：
- **在系统浏览器打开**：外部链接（文档/issue/npm 仓库）的主场景，保持「外部浏览器打开 = 系统默认浏览器」语义（BrowserUtil.browse，行为不变）；
- **在 Pi 内置浏览器打开**：开发验证场景（本地服务、想留在 IDE 内看）；
- **复制链接地址**：所有浏览器上下文菜单的标配项，在富文本聊天流里是拿到原始 URL 的唯一不折腾途径；对「发给别人 / 存进笔记」高频。
- **不加**「始终以此方式打开」：与 US4 三态设置职责重复——想固化就用设置，选择器保持零状态、零记忆（简洁）；**不加**「编辑器预览」：编辑器呈现只对本地 HTML 有意义，聊天链接路由场景 URL 是 http(s)，语义不匹配；**不加**第四项以上：超过 3 项的决策菜单用户是扫读不是阅读，每加一项都稀释前两项的明确性。

### US2 - 与三态设置协调，默认零变化 (P1)
设置 = **系统浏览器（默认）**：点击外链直接系统浏览器打开，无任何弹层（与 037/048 逐字一致）；设置 = **内置浏览器**：直接页签打开；设置 = **每次询问**：弹 US1 选择器（原 Yes/No 模态框移除）。设置下拉文案同步更新（「每次询问 → 打开时询问去向」类）。

### US3 - AI 自主打开内置浏览器验证 (P1)
AI 在会话中开发了 web 功能并启动本地服务后，自主调用 `pi_browser` 工具在内置浏览器页签打开 `http://127.0.0.1:<port>`（工具窗自动切到浏览器页签），用户全程可见（页签前台打开，不是隐蔽动作）。

### US4 - AI 读回页面状态判断成功 (P1)
AI 打开页面后能读回加载状态（loaded/failed）+ 最终 URL + 页面标题 + 正文文本摘录（截断），据此判断「服务起来了 / 页面渲染对了 / 端口错了」并继续行动（改代码、重启服务、换端口）。读回是只读文本快照，不注入任何凭据。

### US5 - 工具条一键外开 (P1)
浏览器页签工具条有「在系统浏览器打开」按钮，把当前页 URL 交给系统默认浏览器。

## 三、验收口径

- US1：ASK 态点击外链 → 选择器出现、三项可选、Enter/点击行为正确、Esc 关闭不打开；复制项真的进剪贴板。
- US2：SYSTEM 默认态逐字回归——点击外链无弹层直接系统浏览器；EMBEDDED 态直接页签；设置页文案更新后中英双语。
- US3/US4（真机完整链路）：用户在聊天输入「起一个静态服务器并自己用内置浏览器验证」→ AI 起 server → 调 `pi_browser` open → 浏览器页签自动打开并加载 → AI 读回含正确标题/文本 → 汇报成功。全程真实鼠标键盘操作（程序化 element.click() 不算数）。
- US4 反向：对不存在的端口调用 open → AI 读回 failed 状态并如实汇报，不幻觉成功。
- US5：按钮点击后系统默认浏览器打开当前 URL。
- 零回归：`gradlew test`、`vitest`、`playwright` 全量基线不破；浏览器页签与 pi 实例页签互不干扰（048 US8 语义不变）；无 JCEF 环境工具调用返回明确失败不崩溃。
- i18n：新增用户可见文案中英双字典。
- verifyPlugin 全 Compatible（只用公开 jcef/org.cef API）。

## 四、Non-goals（本版不做）

- agent 点击/输入/滚动/截图（Cursor 级别交互）——P2，需 CDP/截图管道与前端图片渲染。
- console 日志 / network 流量进上下文——P2（042 P1 已记）。
- 页面评论 → 指令回流（Codex 式批注）——P2/P3（042 P2 已记）。
- 多标签、页内查找、缩放、地址栏历史下拉——042 P3 不变。
- 证书策略放宽——043 范围不变。
- agent 打开行为的持久设置（如「禁止 agent 开外网 URL」开关）——P1 按工具审批机制走（pi-approve 既有 allow/ask 体系覆盖），不新增设置项。

## 五、硬约束（承 048 §五，含本版修订声明）

1. **token 零进入（修订）**：内置浏览器不加载任何带桥接 token 的 URL（`pi_browser.open` 对含本项目 bridge token 的 URL 拒绝）；agent 读回通道（US4）是**对 P0「零 JSQuery 注入」边界的有意修订**——注入脚本为只读快照（title/url/innerText 摘录），不含任何 token/凭据/写操作，且注入目标仅限 agent 主动 open 的页面。chat 面板页保持零注入不变。
2. **file:// 不走主加载路径**：不变（048）。
3. **弹窗禁止静默丢弃**：不变（048）。
4. **下载必须显式 handler**：不变（048）。
5. **单一 windowed 实例**：不变（048 P-7）——agent 只驱动物主项目的工具窗浏览器内核，绝不新建第二个 windowed 实例。
6. **崩溃判定不用 JBCefHealthMonitor**：不变（048 P-6）。
7. **旧帧残留治理**：不变（wasResized workaround）。
8. **日志卫生**：浏览 URL（含 query）与页面文本不以明文进 idea.log；agent-browser HTTP 端点同样脱敏（`LogSafe.url()`）。
9. **agent 读回截断**：正文摘录上限（实现取 ≤3000 字符）+ 注入脚本在页面 CSP 下失败时返回明确错误而非挂起（超时 ≤10s）。
10. **通信面鉴权**：agent-browser 端点独立 per-project token（非 bridge token），token 走自定义 header（浏览器跨域无法携带自定义头 → drive-by POST 天然被拒）；外源 Origin 一律拒绝（承 `BridgeAuth` 语义：null Origin 或自有 Origin 才放行）；端点不进日志。

## 六、开放问题（默认口径，不答则按默认实施）

| # | 问题 | 默认口径 |
|---|---|---|
| Q1 | 工具形态：单工具多 action vs 多工具（browser_open/browser_read…） | **单工具 `pi_browser`**（action: open/read/reload）——省 system prompt 空间、统一返回形状、加新 action 不新增工具；Cursor 的多工具形态是其 agent 自有生态，我们一个扩展一个工具更贴 pi 惯例 |
| Q2 | agent 可开的 URL 范围 | 任意 http(s)——验证场景也可能指向 staging/已部署地址；共享 cookie 风险沿用 048「不承载登录态」文档口径，页签前台打开全程可见；bridge-token URL 显式拒绝（硬约束 1） |
| Q3 | 选择器默认项 | 「在系统浏览器打开」为第一项（Enter 直落）——ASK 态用户点外部链接的最常见意图仍是完整浏览器体验；内置浏览器列第二；复制第三 |
| Q4 | read 失败形态 | 返回 `isError` 结果 + 结构化原因（加载失败原因/超时/无页面），模型可读可重试；不 throw（保住 details 渲染） |
| Q5 | open 等待策略 | 阻塞等待加载完成（≤15s 超时）后一并返回初始快照——模型一次调用拿到「打开+状态」，不需要 open 完再手动 read 一轮 |
| Q6 | US5 按钮图标 | 平台通用图标（`AllIcons` 族，实现时以编译期为准），tooltip 走 bundle |
