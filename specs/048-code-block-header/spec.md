# Feature Specification: 代码块标题栏 —— 语言标签、操作按钮常驻、换行开关、行号

**Feature Branch**: `release/0.5.10`

**Created**: 2026-11-20

**Status**: Implemented（已实现；发布文案见 changelog.d/048-*）

**Input**: 用户提出（2026-11-20，内测第二轮）
> 代码块的 SVG 可以支持渲染吗。加个变更，针对代码块，增加一个类似于标题栏的，左侧显示语言类型，右侧显示按钮，把之前的悬浮按钮样式放到这个栏。再增加一个是否换行的 toggle，默认不换行。
>
> 代码块有行号吗，如果没有把行号加上，要保证鼠标选择文本不能把行号带上。

## 一、意图与边界

用户对消息里的**代码块**提出四项增强，外加一项 SVG 渲染能力：

1. **标题栏（chrome）**：代码块顶部加一条类似 IDE 的标题栏，**左侧显示语言类型**，**右侧显示操作按钮**。
2. **操作按钮搬进标题栏**：上一轮（2026-11-20 早）做的「悬浮才出现在块外上方」操作条改放到标题栏内，**常驻可见**，不再需要悬浮。
3. **换行开关**：标题栏里加一个 toggle，**默认不换行**（保持当前的横向滚动）。
4. **行号**：代码块左侧显示行号；**鼠标选择文本时不能把行号带上**。
5. **```svg 围栏渲染成图**：围栏里的 SVG 源码渲染成图形（此前只有裸 `<svg>` 内联标签会渲染）。

本规格锁定四条边界：

- **只改代码块**。行内图形（裸 SVG、KaTeX 公式）不是代码块，没有标题栏可用，仍用原来的悬浮条（行内小图标上方常驻一条按钮会盖住正文）。
- **不新增 IDE 桥接**。换行开关与行号都是纯前端呈现；「复制 / 在 IDE 打开 / 复制为图片」沿用 041/047 已有的三个入口。
- **SVG 渲染走同一条净化通路**（039 FR-002/FR-003）：不新增第二条 innerHTML 注入路径。
- **不动其它 Markdown 行为**：表格、脚注、diff 高亮、KaTeX、Mermaid 的既有语义全部零回归。

## 二、可行性与现状（读码核实）

- **操作条为何不能直接进 `pre`**：`pre` 是横向滚动容器（`overflow-x:auto`），绝对定位的条会被裁掉；上一轮已经用「壳 `.block-shell` + 条作为 `pre` 的兄弟节点」绕开。本轮把条从「壳的绝对定位子节点」改成「壳内标题栏的静态子节点」，不再需要定位技巧。
- **外壳用 flex + wrap 承载三块**：`.block-shell` 内依次是「标题栏（占满一行）」「行号槽」「`pre`」。这样 `pre` 的父级仍是 `.block-shell`，既有 e2e 的 `pre.locator("xpath=..").locator(".block-actions")` 选择器不必改。
- **`pre` 的浏览器默认外边距会顶偏行号**：`pre` 的 UA 默认 `margin: 1em 0`（12px）在 flex 壳里会把代码整体下移 12px，行号槽与代码行错开。实测（dev server 探针）确认后，把外边距挪到壳上（`.block-shell { margin: 12px 0 }` + 壳内 `pre { margin: 0 }`），行号与代码行对齐误差 < 0.5px。
- **行高是确定的**：`.markdown` 的 `line-height: 1.55` × `pre` 的 `font-size: 12px` = 18.6px/行。行号槽的行高按 JS 量到的**代码行盒**高度写死（同字体同字号），不靠 CSS 猜。
- **换行状态不能放在组件的 ref 里**（实测踩坑）：pi 的 `message_end` 会用权威消息**整条替换** assistant item（新 item id → React 重挂载 → `useRef` 归零），流式结束那一刻 ref 里的状态就没了。改用**模块级**状态表，键取「语言 + 源码开头 48 字」——与消息、与组件实例都无关，重挂载后照样认得；源码在流式中变长时按前缀回溯（键是源码前缀，源码只增不减）。
- **行号与选择文本的隔离**：行号槽是 `pre` 的**兄弟节点**（`pre` 横向滚动，越界元素会被裁掉），并带 `user-select: none` + `aria-hidden="true"` —— 鼠标框选代码时行号既不会被选中、也不会进剪贴板；复制按钮读的仍是 `code.textContent`（源码一个字节没动）。
- **```svg 渲染**：复用 Mermaid 的现成结构——围栏源码经 DOMPurify 净化后插进 `pre` 里的图形容器，源码隐藏但**仍可复制 / 可在 IDE 打开**；画不出东西的（空壳、畸形、只剩 `<script>`）降级回源码显示，且不给「复制为图片」入口（047 FR-007）。

## 三、User Scenarios & Testing

### US1 - 代码块有标题栏，语言和按钮各就各位 (P1)
消息里的代码块顶部出现一条标题栏：左侧是语言类型（`Kotlin` / `Diff` / `SVG`…），右侧是操作按钮（复制、在 IDE 打开、换行；有图形的块还有「复制为图片」）。按钮**一直可见**，不必先悬浮。

### US2 - 行号在代码左侧，且不污染选择 (P1)
代码块左侧逐行显示行号，与代码行一一对齐。用户用鼠标框选代码时，选区里只有代码，行号既不会被选中、也不会被复制进剪贴板。

### US3 - 换行开关 (P1)
标题栏里的「换行」按钮默认关闭（代码不换行，横向滚动）。点一下该块换行，再点一下还原；其它块不受影响；流式结束后开关状态还在。

### US4 - ```svg 围栏渲染成图 (P1)
pi 回复里的 ```svg 代码块渲染成图形（而不是一坨源码）。源码仍可复制、仍可在 IDE 中打开。围栏里的恶意 SVG（`<script>` 等）照旧被净化，不执行、不渲染。

## 四、Requirements

- **FR-001** 代码块 MUST 有标题栏：左侧显示语言类型（MUST 取自围栏的 `language-*`，无语言时给中性标签），右侧显示操作按钮。按钮 MUST 常驻可见（不依赖悬浮）。
- **FR-002** 标题栏按钮 MUST 沿用 041/047 既有入口（复制 / 在 IDE 打开 / 复制为图片），外观 MUST 与既有 `.block-action-btn` 一致；MUST NOT 新增 IDE 桥接方法。
- **FR-003** 代码块 MUST 有换行开关，**默认关闭**（不换行、横向滚动）；开关 MUST 只作用于该块；状态 MUST 在流式重建 / 组件重挂载后仍然保持。
- **FR-004** 代码块 MUST 显示行号，行号 MUST 与代码行逐行对齐（换行模式下按逻辑行对齐）；行号 MUST NOT 进入鼠标选区、 MUST NOT 进入剪贴板；MUST NOT 改变复制/「在 IDE 打开」读到的源码文本。
- **FR-005** ```svg 围栏 MUST 渲染成图形，渲染 MUST 经 DOMPurify 净化（039 FR-002/FR-003 的单一入口）；源码 MUST 仍可复制、可在 IDE 打开；净化后画不出东西的 MUST 降级回源码显示且 MUST NOT 出现「复制为图片」入口。
- **FR-006** 行内图形（裸 SVG、KaTeX）不是代码块，MUST 保持既有悬浮条行为（常驻按钮会盖住正文）。
- **FR-007** 本增强 MUST NOT 回归：Markdown 其它语法（表格、脚注、diff 高亮、KaTeX、Mermaid）、041「在 IDE 打开」、047「复制为图片」、008 双语。
- **FR-008** 标题栏/行号/换行的呈现 MUST 与面板主题一致（深色下面板不得出现浅色块）。

## 五、Decisions（2026-11-20）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 按钮是常驻还是仍然悬浮 | **常驻**在标题栏内（用户原话「把之前的悬浮按钮样式放到这个栏」；标题栏本来就是常驻控件的位置） |
| Q2 | 行内图形要不要也有标题栏 | **不要**。行内图形没有代码块可依托，常驻按钮会盖住正文 → 行内图形保留悬浮条 |
| Q3 | 换行开关的默认值 | **默认不换行**（用户明确要求），开关按块生效 |
| Q4 | 换行状态存哪 | **模块级状态表**（组件 ref 会被 `message_end` 的整条替换冲掉，实测确认），键 = 语言 + 源码前 48 字 |
| Q5 | ```svg 渲染后源码还看得到吗 | **隐藏**（与 Mermaid 同构）：图形在上、源码隐藏，但复制按钮复制的是源码、「在 IDE 打开」打开的也是源码 |
| Q6 | 行号与选择文本 | 行号槽独立于 `pre` + `user-select:none` + `aria-hidden` → 选区与剪贴板都不含行号 |

## 六、不做的事

- 不给行内图形（裸 SVG / KaTeX）加标题栏或行号。
- 不做「按语言记住换行偏好」的全局设置（只做按块）。
- 不新增 IDE 桥接方法、不新增 npm 依赖。
- 不做代码块折叠 / 展开、不做全屏编辑。

## 七、与既有规格的关系

- **039（内联 SVG）**：本规格**改写**其 #6 边界——「围栏 = 源码、绝不渲染」被用户的新要求推翻：围栏里的 SVG 现在也渲染成图（源码仍可复制）。039 的净化口径（FR-002/FR-003）不变，另补一条：`<style>` 一并禁掉（DOMPurify 不清洗 style 的文本内容，里面的 `@import` / `url(http…)` 是外链向量）。
- **041（代码块在 IDE 打开）**：按钮位置从「块外上方悬浮条」改为「标题栏内常驻」；点击语义、桥接契约不变。
- **047（复制为图片）**：按钮随 041 一起搬进标题栏；新增「```svg 围栏渲染出的图形」也是可复制为图片的渲染块。
- **040（KaTeX / Mermaid）**：Mermaid 的图形仍留在自己的 `pre` 里（标题栏照常），KaTeX 公式块不受影响。

## 九、二次修订（2026-11-20，内测第三轮）

用户在同一轮提出新要求（见 [049 规格](../049-code-block-view-mode/spec.md)）：

> 现状描述：代码块 svg mmd 等默认是渲染模式。期望增加切换为代码默认，两种模式切换，只有代码默认换行切换才有效。

对 048 的影响只有一条，其余不变：

- **FR-003（换行开关）收窄**：换行开关仍然默认关闭、仍然按块生效、仍然记住用户的选择，
  但**只在源码显示着的时候才有效** —— 渲染成图的块里没有「行」可换，按钮置灰。
  048 原文本「代码块 MUST 有换行开关」补一句：开关的可用性跟着「代码是不是真的显示着」走。
- **FR-005（```svg 渲染）不变**，但渲染出来的图形现在**记住自己来自哪份源码**
  （`data-mermaid-marker`）：流式期间同一份源码可能同时有多个渲染请求在飞，
  后来的请求会返回 `null`，`null` 只说明「这次没画成」，不代表屏幕上那张图是错的 ——
  只有属于**另一份**源码的图形才允许被撤掉。（这条修掉了一个会让 mermaid 图形
  永远停在源码上的老账，048 当时没暴露出来。）
- **标题栏新增一个按钮**（`.code-source-btn`）：普通代码块**不**出现该按钮。

## 十、三次修订（2026-11-20，内测第四轮）

用户要求：

> 复制为图标按钮，放到复制按钮左侧

即：**代码块标题栏里的「复制为图片」按钮挪到「复制」按钮的左边**（即操作栏最左）。

- 标题栏按钮顺序定为：**复制为图片 / 复制 / 在 IDE 打开 / 源码 / 换行**。
- **实现要点**：该入口是等图形渲染出来之后才有的（图形没画出来就没有可复制的图），
  所以它天然「后到」——`appendChild` 会让它掉到操作栏最右边。必须
  `insertBefore(firstChild)` 才能让它稳定待在最左：**顺序不受到达时机影响**。
- **行内图形不受影响**：裸 SVG / KaTeX 不是代码块、没有标题栏，它们的悬浮条里
  只有「复制为图片」一个按钮，没有左右可谈。

## 十一、四次修订（2026-11-20，内测第五轮）

用户看真机截图后反馈：

> 行号是不是太靠左了，有点别扭

**实测定位**（按用户截图逐像素量，2x）：代码块左边框在 x=79，行号数字起点
x=82（**只差约 1.5px，几乎粘在边框上**），数字终点 x=106，而行号槽的右分隔线
在 x=126（**数字与分隔线之间空了约 10px**）。数字被夹在「贴住外边框」与
「离自己的代码很远」之间 —— 这就是别扭的来源。

**改法**（049 之后的小修订）：

- 行号槽左内边距 0 → **8px**：数字不再粘着代码块边框。
- 行号槽右内边距 8px → **4px**，且壳内 `pre` 的左内边距 10px → **6px**：
  数字到代码首字符的距离由 19px 收到 **11px**，数字与代码成一对。
- 代码本体位置基本不动（净位移 < 2px），只有行号列变宽了 4px。

## 十二、五次修订（2026-11-20，真机 r57 发现的布局缺陷）

真机验证（WebStorm 2026.2，面板 450px）发现：**代码最长行一超过面板宽，
行号槽就和代码分家** —— 行号独占一行悬在代码上方，代码掉到下一行，
行号与代码行对齐无从谈起（e2e 全绿是因为默认视口 1280px 复现不了窄面板）。

**实测定位**：壳 `.block-shell` 是 `flex-wrap: wrap`，`pre` 的 flex basis 是
`auto`（对 `<pre>` 取 max-content）。横向放不下时 wrap 的判定用的是 base
尺寸（max-content ≈ 最长行宽），`min-width: 0` 只约束最终尺寸、不参与换行
判定 → `pre` 整个被换到下一行。行号槽（flex 0 0 auto）只能自占一行。
断行只由「最长行宽 > 可用宽」触发：同一面板上 19 字符的块并排正常、
82 字符的块分家。

**改法**：`pre` 的 basis `auto` → **`0%`**（`flex: 1 1 0%`）。basis 为 0 后
`pre` 永远与行号槽同排（grow 吃剩余宽），长行交给 `overflow-x: auto` 横向
滚动 —— 与 FR-003 的默认不换行语义本来就一致。

**验收**（双端）：
- e2e 新增窄视口（460px）用例：最长行 > 容器宽时 `gutter.top === pre.top`、
  `pre.left >= gutter.right`、长行确实横向溢出（夹具 `?md=longline`）；
  修复前该用例 RED（sideBySide=false），修复后连同 header/换行/行号/049/
  块操作/复制为图片 25 条全绿，vitest 509、typecheck 0。
- 真机 r58 复验（同一 115 字符长行块）：行号与代码并排、每行行号与代码行
  中心偏差 ≤ 0.2px、边框→数字 9px、数字→代码首字符 11px（四次修订的两个
  目标值原样保持）、长行横向滚动。
