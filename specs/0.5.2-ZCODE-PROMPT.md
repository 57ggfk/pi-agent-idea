## 硬约束（违反即失败）

1. **分支**：已在 `release/0.5.2` 上，`build.gradle.kts` 的 `version` 已是 `0.5.2`。
   **不要**改版本号、**不要** `publishPlugin`、**不要** `git push`、**不要**合并 `main`、**不要**打 tag。
2. **提交时间**：提交必须避开 09:00–17:00（只允许 12:00–12:59 与 17:00–次日 08:59）。
   每次提交显式设置两个日期：

   ```bash
   ts=$(date +%Y-%m-%dT%H:%M:%S%z)
   GIT_AUTHOR_DATE="$ts" GIT_COMMITTER_DATE="$ts" git commit -F /tmp/msg.txt -- <paths>
   ```

   若当前时钟落在 09:00–11:59 或 13:00–16:59，把 `ts` 设成最近一个合法窗口内的时刻，
   并在 run report 里记一行「时间窗口内提交受限，使用 N 时刻时间戳」。
3. **双端契约同步**：任何新增桥接方法，必须同时改
   `src/main/kotlin/dev/pi/agent/bridge/BridgeService.kt`（dispatch 白名单）、
   `web/src/bridge/types.ts`（`BridgeMethod` 联合类型）、`web/src/bridge/mock.ts`（mock 实现），
   以及需要协议行为时的 `test/mock-pi/mock-pi.mjs`。四者不同步视为未完成。
4. **依赖只准加两个**：web 侧**仅允许**新增 `i18next` 与 `react-i18next`（008 的国际化底座，理由见
   `specs/008-i18n/plan.md` 的 D0）。**禁止**再加 `i18next-http-backend`、`i18next-browser-languagedetector`、
   `i18next-icu` 或任何其他 i18n 相关包——字典按语言拆 chunk 走 Vite 的 `import.meta.glob`，语言来源是
   IDE 传入的 `env.locale`，复数是 i18next 原生的 CLDR 后缀方案。Kotlin 侧不加库。
5. **不动用户环境**：不修改 `~/.pi/**` 下任何配置（既有功能路径除外），不执行破坏性命令，
   不 `rm -rf`，不全局安装。
6. **不伪造通过**：不允许删除/跳过失败测试来变绿；不允许把「没跑」写成「通过」；
   run report 里每个「通过」都要附命令或测试名。
7. **动作注册位置**：`<group>`/`<action>` 只能写在 `plugin.xml` 顶层的 `<actions>` 内，
   写进 `<extensions>` 会被静默忽略（宪法「技术约束」）。
8. **品牌名不翻译**：`Pi Agent`、工具窗 id、action id 不改。

## 问题处理原则

- **简单问题**（编译错误、类型错误、样式细节、测试选择器失效、文案不一致）：直接修，继续走。
- **复杂问题**（协议语义不明、JCEF 行为与 Chromium 不一致、跨 IDE 兼容性、性能不达标、
  规格与代码根本冲突）：不要硬改。记录到 `specs/0.5.2-run-report.md` 第 4 节
  （现象 / 已排查 / 猜测根因 / 建议下一步 / 影响面），实现上取**最保守的可用路径**，继续下一个任务。
- 特别地，`specs/007-message-fork/plan.md` 的 **V1/V2 协议验证是阻塞项**：
  必须先实测 `fork` 的边界语义，把结论写回 plan.md 与 `fork-semantics.json`，再决定实现。
  若结论是「新会话包含该 entry」，按 plan 的方案 B 降级（中间回复不显示 Fork 按钮），
  并把限制写进 run report 第 6 节与 CHANGELOG 的「已知限制」。
